# Signup 429 Error Fix Documentation\n\n## Problem\nUsers were failing to sign up with **429 (Too Many Requests)** errors from Supabase Auth. This happened when:\n1. Users clicked the signup button multiple times accidentally\n2. Browser auto-retry logic triggered duplicate requests\n3. Form was re-rendered without submission guard\n\n## Solution\n\n### Three-Layer Protection Against 429 Errors\n\n#### 1. **Submission Guard** (`isSubmitting` flag)\n- Once a user clicks \"Create account\", the flag is set to `true`\n- Any subsequent submit attempts while flag is `true` are ignored\n- This prevents accidental double-clicks or browser auto-retry from sending duplicate requests\n- Flag is only reset after the request completes (success or error)\n\n**Code:**\n```typescript\nif (isSubmitting) {\n  console.warn('Submission already in progress — ignoring duplicate request')\n  return\n}\nsetIsSubmitting(true)\n// ... make request ...\nsetIsSubmitting(false)  // Reset only after complete\n```\n\n#### 2. **Rate Limit Cooldown** (120 seconds)\n- If Supabase returns a 429 error, activate a 120-second cooldown\n- All form inputs and buttons are disabled during cooldown\n- Countdown timer displays on the button: \"Wait 120s before retrying\"\n- Error message shows: \"Too many signup attempts right now. Please wait at least 60 seconds before trying again.\"\n- This respects Supabase's enforced minimum wait window\n\n**Code:**\n```typescript\nif (error.message?.includes('429') || error.message?.includes('rate limit')) {\n  setError('Too many signup attempts right now...')\n  setRateLimitCooldown(120)  // Block for 120s\n}\n```\n\n#### 3. **Referral Policy Enforcement**\n- Referral code validation happens **before** submitting to Supabase\n- If referral code is not valid, signup is blocked with clear message\n- This prevents wasting API calls on users who don't meet requirements\n- Validation feedback shows in real-time as user types: \"Checking code...\" → \"✓ Valid\" or \"✗ Invalid\"\n\n**Policy Maintained:**\n- ✅ Full name required\n- ✅ Email required and normalized (trimmed + lowercase)\n- ✅ Password required (min 6 chars)\n- ✅ **Referral code required and must be from verified Pulse member**\n- ✅ Referral code validated before attempting signup\n\n### Additional Protections\n\n#### Email Normalization\nAll emails are trimmed and converted to lowercase before submission:\n```typescript\nconst cleanEmail = email.trim().toLowerCase()\nawait supabase.auth.signUp({ email: cleanEmail, ... })\n```\n\n#### Detailed Error Messages\nSpecific errors are caught and user-friendly messages are shown:\n- \"Too many signup attempts\" → Rate limit detected\n- \"This email is already registered\" → Email already exists\n- \"Please enter a valid email address\" → Invalid email format\n- \"[generic error]\" → Any other error\n\n#### Login Flow Protection\nSame submission guard and error handling applied to login.\n\n#### Resend Confirmation Email (Sign-up Success Page)\n- Resend button has 60-second cooldown to prevent rate limiting\n- Button is disabled during cooldown with countdown display\n- Clear feedback messages for user\n- Respects Supabase rate limiting on resend endpoint\n\n## User Experience Flow\n\n### Happy Path (Successful Signup)\n1. User fills form with valid referral code\n2. Clicks \"Create account\"\n3. Button shows loading spinner, form disabled\n4. Request sent to Supabase (only one time)\n5. User redirected to sign-up confirmation page\n6. Confirmation email sent by Supabase\n7. User clicks link in email\n8. User signs in with their credentials\n\n### Error Path (Invalid Referral Code)\n1. User enters invalid referral code\n2. Real-time validation shows \"✗ Invalid — we couldn't find a Pulse account with that code\"\n3. Submit button remains disabled (red text underneath shows why)\n4. User must enter valid code before signup is possible\n5. No request to Supabase sent until referral is valid\n\n### Error Path (Rate Limited - 429)\n1. (Unlikely with submission guard, but if it happens)\n2. User sees: \"Too many signup attempts right now. Please wait at least 60 seconds before trying again. (Try again in 120s)\"\n3. All form fields disabled\n4. Button shows \"Wait 120s before retrying\"\n5. Countdown ticks down: 120s → 119s → ... → 0s\n6. After 120s, form is re-enabled and user can try again\n7. No automatic retry - user must click button\n\n## Testing the Fix\n\n### Test 1: Double-Click Prevention\n1. Go to `/auth/sign-up`\n2. Fill form with valid referral code\n3. Rapidly click \"Create account\" 5+ times\n4. ✅ Only ONE request is sent to Supabase (check network tab)\n\n### Test 2: Referral Validation\n1. Go to `/auth/sign-up`\n2. However, for extra protection, enable CAPTCHA:\n\n### Optional: Enable CAPTCHA in Supabase (Recommended)\n1. Go to Supabase Dashboard\n2. Authentication → CAPTCHA\n3. Enable CAPTCHA for \"Sign up\"\n4. Save configuration\n5. CAPTCHA will automatically appear on signup form\n6. This prevents bot abuse and automated repeated signup attempts\n\n## Code Changes\n\n### Files Modified\n1. **`components/pulse/auth-form.tsx`**\n   - Added `isSubmitting` state\n   - Added `rateLimitCooldown` state\n   - Added submission guard checks\n   - Added rate limit detection and cooldown logic\n   - Added email normalization\n   - Enhanced error messages\n   - Disabled form inputs/button during submission or cooldown\n   - Added countdown display on button\n\n2. **`app/auth/sign-up-success/page.tsx`**\n   - Converted from static to dynamic with resend functionality\n   - Added `resendCooldown` state\n   - Added resend email handler with cooldown protection\n   - Added visual feedback for resend status\n   - Added countdown for resend button\n\n### No Changes Needed\n- Supabase configuration (keeping default email sender)\n- Database schema\n- Middleware\n- Server actions (pulse.ts)\n\n## Deployment\n\n1.
